# Vision_7.0 使用说明（基于Vision5.0）

## 2026-10-16 直道右纠偏

- 根据“机器人一直偏左但视觉仍直行”的实拍，右纠偏进入线由左边线画宽比 0.34 提前到 0.22，退出线为 0.18。
- 双边确认缩短到 0.08 秒，单边确认 0.12 秒；单双边切换时保留同方向确认。
- 已确认贴近左边线且比例超过 0.38 时，右避边优先于左弯保持。
- 仅修改直道位置纠偏；图形、障碍物、一次发送和串口包格式不变。

## 2026-10-16 窄道兼容

- 只有双边可见并确认宽道时，才使用提前右纠偏；单边画面无法判断宽度，一律使用原保守阈值。
- 双边宽度用一秒窗口的下四分位判断，持续变窄 0.45 秒后锁定窄道，避免摆动瞬间误切换。
- 修复左弯显示角与实际下发角不一致：弯道、转弯记忆和短时丢线保留真实弯道角，仅位置避边使用位置误差角。

7.0新增独立长横杆检测与AA58角度包；原六种图形识别模块`shape_tracker.py`未修改，AA55图形包、AA56巡线控制和AA57反馈保持原协议。完整触发规则与实机边界见上级`README_7.0.md`。

新版位于 `HumanoidRobot/5.0/Vision5.0`，基于当前保存的 `1.0/Vision` 巡线、串口和相机恢复代码。旧目录未修改。

## 运行

在 CanMV IDE 中打开本目录 **main.py** 运行，或把它作为开发板启动脚本。它已合并全部运行模块，无需上传其他 Python 文件；`canmv_line_follow_single.py` 内容相同。

- 画面版本标记：`VISION5_CARD_V1`。
- 保留 VGA 灰度采集、180°翻转，UART1 TX=GPIO40 / RX=GPIO41，115200。
- 保留巡线 AA55、角度 AA56、主板 AA57 反馈，以及原来的相机故障恢复。
- 新版已彻底移除正对障碍模块、标定参数、分析调用、AA58 编码/发送及对应显示，不是仅关闭开关。STM32 工程未修改。
- 修改模块后运行 `python build_standalone.py` 重新生成两个单文件入口，不要只改生成文件。

## 图形识别

编号保持：1=方框内圆，2=方框内五角星，3=方框内方形，4=方框内菱形，5=方框内十字，6=方框内三角形。

识别不再使用巡线计算出的阈值：六档灰度寻找外方框候选，取四角作双线性校正，再用卡片局部明暗对比提取内部图案，与六类几何模板比较。要求外框四边支持、模板分数及第一/第二名差距同时达标。双线性校正用于中等倾斜，并非完整投影标定；严重遮挡或外框不完整时拒识。

最高每100ms检测一次，同一位置、同一编号连续两次通过才加入发送队列。确认后立即发送，不再等待卡片到脚下。每种图形从串口成功写出开始冷却10秒，沿用当前源代码行为；不是整次运行只能发送一次。未发送时不会重复入队。

识别区为640×480画面的 y=126..441，排除录像上方文字与底部机体；卡片必须完整进入该区域。候选宽40..280、高38..280像素。算法在绘制预览之前读取原始帧；录屏自带的十字/文字无法从历史视频中去掉。

## 板端待测与限制

尚未连接K230D，未验证板上FPS、CanMV原生连通域差异或STM32实际收包。录像原有FPS文字是旧程序的显示，不是本版性能；截图新增绿色框和绿色文字才是新版回放结果。

圆形完整可识别窗口很短，本次仅两个相邻采样通过；如果板端达不到检测频率，仍可能漏识别。运行后观察串口 `shape ...ms / max ...ms` 和 `SHAPE n CONFIRMED`，并确认画面标记为VISION5_CARD_V1。若相机固定方向发生变化，需要重新验证而不能认为六类模板对任意旋转均已验证。

参数集中在 `shape_tracker.py`（灰度档位、候选大小、分数0.82、分差0.065、边支持0.60）和 `main_modular.py`（检测间隔100ms、冷却10秒）。优先检查卡片是否完整进入识别区和运行速度，再针对实机样本调参。
