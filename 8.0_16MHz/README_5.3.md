## 关键故障及修复

Vision5.0的resolve_control在status4发送非零位置误差；5.1的Vision_FeedByte却仅允许status2/3携带非零值，导致右纠包被计为field_errors并丢弃。已对两份实际ARM固件输入相同status4、angle=50（5度）数据包：5.1字段错误1次且没有更新方向，5.3字段错误0次且方向为4。证据：Validation/protocol_before_after.json。

5.3允许status4携带合法的-900..900数据。负值在右纠计算中按0处理，不反向；状态0/1/5仍要求角度0，CRC和范围检查保留。

右纠偏从固定-62计数改为 -(62+round(max(0,位置等效角)*4))，绝对值最多100：0度62、1度66、5度82、9.5度及以上100计数。参数为RIGHT_RECOVER_BASE_COUNTS、RIGHT_RECOVER_COUNTS_PER_DEGREE、RIGHT_RECOVER_MAX_COUNTS。100计数是本次试机值，尚未验证机械稳定性；若右纠明显过量，可先把MAX改回62，仅保留收包和提前触发修复。

视觉更早介入并加退出滞回：左边线进入阈值22%画宽、退出18%；双边80ms、单边120ms确认。同方向单双边切换不清除确认；超过38%的已确认右避边优先于左弯记忆。详细参数及回放限制见Vision5.1/README.md。

## 沿用的行为

原my_actionsfinalorigin2.json、第6帧起始、六帧循环、原位置（除既有髋纠偏叠加）、单关节时序、速度、ACC、图形保持时间、16MHz晶振/168MHz系统时钟、TOF关闭均沿用5.1。action_frames.h、shape_frames.h和原JSON逐字节比较相同。

不在当前插值中途重写目标：新请求沿用原逻辑在后续帧入口作用；不是等完整一轮才接收，也不是中途跳舵机。丢线/WAIT不清除最近有效运动，手动停止仍优先。

## 上板核对

烧录本目录5.3 HEX，并运行Vision5.1/main.py。主板启动文字应为HumanoidRobot 5.3 boot，视觉标记应为VISION5_1_RIGHT_RECOVERY。先复测同一直道，观察右纠时是否实际回轨、退出后是否再次持续左偏，再复测左弯。若仍偏，不要同时改原步态和多组舵机参数；保留录像与屏幕E值，以本版参数为单项调整起点。
