# 7.0：小碎步对正与越障

本目录由6.0完整复制后独立修改；6.0、Vision5.0原目录未修改。视觉程序位于`Vision_7.0`，主控工程为`MDK-ARM/HumanoidRobot_7_0.uvprojx`。

## 实际控制顺序

1. 100 mm以外保持6.0正常步态，原巡线、AA56方向控制和六种图形识别继续工作。
2. Vision_7.0连续3帧确认“跨越较宽画面的近水平长横杆”，通过新增AA58发送横杆角度。图形仍使用原AA55，`shape_tracker.py`未修改。
3. HC-SR04在正常步态和小碎步期间持续进行非阻塞测距；无回波或超量程结果不发布、不参与计数。连续3次有效距离小于100 mm，就在下一个帧边界启用小碎步，不要求视觉先确认横杆。一旦启用就一直保持小碎步直到越障，后续距离变远也不再切回大步幅。
4. 小碎步完整使用`Actions/my_actionsfinalshort3.json`的6帧位置、时长、停留、速度、ACC和单舵机时序。正常步态与小碎步先完成当前动作组的“落地→离地”，再由另一动作组的800 ms前摆接续，避免在200 ms离地帧中硬切动作表。
5. 距离45～80 mm且横杆角绝对值不大于8度，启动越障。若仍未对正但距离已经小于45 mm，也启动越障，避免继续逼近。
6. 越障只在小碎步的计划落地帧开始，完整执行`Actions/my_actions strideover4.json`的16帧。第16帧已经是“左脚前摆”（1200 ms运动、400 ms停留），随后直接接`my_actionsfinalorigin4.json`的“左脚落地”，再继续正常直走；不会重复左脚前摆。

小碎步髋修正参数已经放在`Inc/robot_config.h`最前面：视觉角默认先除以1.5（`OBSTACLE_ANGLE_DIVISOR_X10=15`），再按每度12计数计算，最大240计数。`15`改为`10`即恢复1:1；需要继续加大时再修改`OBSTACLE_HIP_COUNTS_PER_DEGREE`或`OBSTACLE_HIP_MAX_COUNTS`。

## 防误触发边界

- 小碎步由连续3次小于100 mm的有效超声结果直接触发；单次近距不会触发。
- 小碎步触发后锁存；距离抖动、瞬时变远或无效回波都不能恢复大步幅。只在完整越障结束、紧急卸力或重新上电时清除。
- 无回波和超量程结果直接忽略，不向运动控制发布距离事件。
- 视觉横杆不再作为进入小碎步的前置条件，只用于左右朝向调整和45～80 mm对正判断。
- 横杆要求长度至少260 VGA像素、相对水平不超过35度、连续3次出现；十字卡片宽度不足，不进入障碍通道。
- 障碍检测只读原灰度帧，不向图形分类器写入阈值、候选框或状态。原`shape_tracker.py`与Vision5.0逐字节一致。

## 协议

- AA55、AA56、AA57保持原格式。
- 新增AA58：`AA 58 seq flags angle_lo angle_hi CRC_lo CRC_hi`。
- `flags bit0=1`表示稳定横杆；`angle`是横杆相对水平角，单位0.1度；CRC仍为CRC16-CCITT-FALSE。

- Keil全量编译：0错误；固件`MDK-ARM/HumanoidRobot_7_0/HumanoidRobot_7_0.hex`。
